# Submission: project description

**Flaky or real? Let Drex decide.** CI pipelines make an unpriced bet every time a test fails: is it flaky, or is it a real bug? Frontier LLMs answer with a confident yes or no that carries no calibrated uncertainty, which gives you nothing to tune. We hand that decision to Drex. NDI (Nace Document Intelligence) extracts structured fields from raw CI failure logs: error type, test name, timing, infra signals, and retry history. Drex returns a calibrated P(flaky). A two-threshold policy turns that probability into QUARANTINE, RETRY, or BLOCK-and-alert. The loop runs as an Intern session, the Nace harness: Drex is System 1, a DeepInfra model is System 2, and they call extract, decide, act and feedback tools. Human corrections then recalibrate the thresholds against an explicit cost table, where wrongly quarantining a real bug is the expensive mistake, and the thresholds move only when the cost table says moving them lowers total cost. We benchmarked the loop against a frontier open LLM on DeepInfra on the same labeled failures. On 60 labeled failures (drex-max-v1.1, real API calls), Drex reached 96.7% accuracy versus [RESULT: LLM accuracy], wrongly quarantined 0 real bugs versus [RESULT: LLM count], and had lower expected cost (118 vs [RESULT: LLM cost]) at 292 ms median latency and about $0.07 per thousand decisions. Every real regression scored P(flaky) ≤ 0.35, and 34 of 36 flaky failures scored ≥ 0.93. A 'retry passed ⇒ flaky' rule quarantined 2 real bugs that Drex blocked. In the learning step, 16 human labels changed 0 decisions. The refit kept the thresholds at 0.40/0.80, and forcing a fix for the one confident disagreement would have raised cost from 118 to 484, so the loop held.
